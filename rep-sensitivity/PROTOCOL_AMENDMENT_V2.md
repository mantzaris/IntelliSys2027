# Continuation amendment: interpretation and fixed-input root diagnostic

Recorded 16 October 2026, after the original main freeze and amendment v1. Original
H1–H4, v1 P1–P3, all frozen corpora and accepted responses remain unchanged. At
this amendment, original main Qwen3 is running and Phi-4 is queued. Only progress,
hashes, settings and timing have been inspected from original held-out execution;
no held-out decision outcomes informed this design. Pilot reanalyses are exploratory.

The question is when repetition improves the preservation **and application** of
information, and when it impairs response to scoped differences, conflicts,
exceptions or updates. Competing explanations remain retention, numerical
comparison, influence of emphasized claims, lost exceptions, fresh computation,
position/formatting and output validity. Neither a benefit nor harm is required.

The completed v2 pilot interpretation reports absolute accuracies, matched
improvements/regressions, equal-base effects, leave-one-base-out sensitivity,
paired-world success and deterministic multi-label failure locations. It does not
replace the original analysis. See `PILOT_INTERPRETATION.md` and its source JSON.
The public registry binds the entire proposition to its key; a value at another
key is not successful retention. Annotation of attention or hidden computation
would require a separate audited procedure and is not claimed.

The original frozen extension repeats a numerical objective only when target C's
eligibility permits it. Its COMMON target can instead be a Boolean finding. It
therefore does not estimate a balanced numerical-objective effect. The addition
fills that gap without changing existing target eligibility.

The v1 deterministic transport consolidates identical values into one assertion
with multiple references. Repetition there changes the reference list, rather
than preserving four literal assertion presentations. Thus its interaction also
changes consolidation. The new lossless root-only arm repeats assertion text
itself, separating this additional distinction; neither comparison alone is a
pure causal decomposition of the original hierarchy effect.

A pre-inference analysis supplement, `scripts/audit_root_information.py`, separates
world-oracle correctness from the decision warranted by the root's actual inputs.
If visible claims admit several decisions, the latter expects INSUFFICIENT. A
consistent but wrong summary may uniquely warrant a world-incorrect choice; that
is recorded as a transmission problem rather than blaming the root for unavailable
truth. Missing values are never filled from the evaluator. This supplement changes
no frozen prompt, eligibility, accepted score or execution snapshot; it writes a
separate `visible-information.json` after the diagnostic completes.

## Root diagnostic v1

Development scheduling indices `[0,1,2,6,7,8]` include both worlds, six independent
bases, one stochastic repetition. The original frozen reports and historical
ordinary/single/repetition-0 manager calls determine inputs. Two incoming interfaces:

1. Fixed historical model summaries, including their original errors.
2. Deterministic transport of the supplied worker assertions and original scope
   keys/citations. This has no oracle correction, final answer or hidden labels.

Within each fixed interface, the arms are no added repetition; each of the three
candidate objectives separately; a prespecified Boolean-critical constraint;
all objective propositions uniformly; neutral padding; and end placement.
Only the first occurrence of a selected scoped assertion receives three added
copies, preserving its exact value and references. Existing duplicates or
conflicts remain; baseline and added presentation counts are recorded. Missing
selected assertions cause an explicit ineligible cell, never truth-based repair.
Uniform objectives is **not** uniform repetition of every required report; v1 E
provides that latter comparison.

The neutral/end target is chosen by seed from all candidate objectives, without
oracle-choice selection. Padding uses native whole-prompt token matching and
records residuals; it appears at the end and does not perfectly match adjacent
copy positions. Both end-versus-adjacent and evidence-versus-padding comparisons
match the same selected objective. No additional worker executions or observations
occur. The model's instructions, scope/ancestry registry and output cap are common.

The manifest has 192 planned root calls/trajectories, subject only to documented
input eligibility (CPU inspection finds none missing). Reused historical manager
calls are inventoried separately from marginal new root computation. It is a
six-base diagnostic, not a powered confirmation. Family × change strata have one
base each; intervals are withheld rather than reporting degenerate precision.
Point estimates average within base first. The transport interaction is tested
as a difference of repetition effects on common eligible cells, not a difference
in separate significance labels. No causal mediation claim follows from this
comparison or from conditioning on observed retention.

The core v1 confirmation remains separate: fresh validation indices 36–59 and
held-out indices starting at 384; scheduling is primary and workflow secondary.
Its 24/48 total-pair allocation (12/24 primary scheduling bases) uses the fixed
validation competence, variance and runtime rule, never effect sign or significance.
No repeated enlargement is authorized. New root-only/near-overlap comparisons are
exploratory unless a later, separately frozen confirmation is justified.

## Compute and provenance

The waiting v1 controller retains its existing order and immutable implementation.
The new root diagnostic waits until both original model stages and the frozen v1
extension finish. It adds no competing GPU process. Native-token CPU preflight
must fit every input plus the unchanged output cap and project below one allocated
inference hour using the measured validation root-call 95th percentile. This is a
planning bound, not a billing-rate claim; actual times and model reload are logged.

Every accepted call uses the existing ledger and request hash, including trial,
repetition, prompt and model settings. Malformed completed responses remain errors.
Freeze records link config, source, tests, preflight and source-pilot hashes;
snapshots preserve inference despite subsequent working-tree edits. Local mirrors
retain the raw outputs outside Git. Completion automation now waits for this
diagnostic as well, and never declares human review or submission readiness.

No optional boundary investigation has been selected before core development
results exist. At most two may be justified afterward. Existing placement and
overlap controls should resolve their questions before any new scale or task
family is added. The present allocation adds only the targeted root diagnostic.
