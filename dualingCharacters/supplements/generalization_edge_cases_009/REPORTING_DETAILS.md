# Reporting and diagnostic scope

The frozen `analysis.py` computes the primary endpoint, trajectories, memory changes and eligible repetition. `report.py` aggregates these frozen measurements and draws figures. It also separates the already specified direct/communication opportunity strata from raw action records; this does not redefine their denominators.

The descriptive exposure audit in `exposure.py` was added after reading the fixed Qwen illustrative panels, before the second backbone completed. It reports which decisive fields coincide with the originally assigned owned slots, how many post-event direct actions address those fields, and continued owned-goal actions where an actual revision moves away from that option. This is a contextual diagnostic, not a new primary endpoint or causal test. Its chronology is explicit because examples motivated checking the amount of relevant exposure. No script, condition, cast, seed, inference or scientific freeze was changed in response.

The figure and dialogue renderers are presentation code. Case identities and the first post-decision direct opportunity were fixed before research generation. All added prose interpretations are AI-assisted and remain separate from mechanical counts. Counterexamples, if displayed, are purposive and do not enter prevalence estimates.

The clarification breakdown in `trajectory_details.py` was implemented after the main outcomes were available. It expands the prespecified clarification endpoint into missed required questions, nonnull commitments during pending states, and unnecessary field-specific questions. These are **post-run descriptive diagnostics**, not additional preregistered primary results. They were not used to alter the benchmark, allocation, inference, selection or primary analysis. The same distinction applies to the ownership-exposure audit. The frozen primary code and outputs remain unchanged; the later code is separately hashed in `DESCRIPTIVE_REPORTING_MANIFEST.json`.
