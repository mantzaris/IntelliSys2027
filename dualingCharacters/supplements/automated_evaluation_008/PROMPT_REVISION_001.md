# Single permitted shared prompt revision

After the first Phi development-only40-control run, before any held-out/research inference, the recorded outputs showed capped JSON, citations to user context instead of the selected claim, and overfilled assertion arrays. Qwen is independently profiled under the original instructions as a baseline engineering check. No research condition labels or held-out outcomes informed this revision.

The final shared instructions explicitly show the output skeleton, restrict positive claim spans to the selected statement and recipient spans to the first follow-up, require empty arrays when no selected authorization assertion exists, and bound explanation/quote lengths. The output allowance becomes1024tokens for both judges. A temporal-scope field distinguishes currently binding from explicitly historical/uncertain assertions; only current unambiguous extractions are compared to current ledger truth. A current-ledger mismatch is not itself proof of deception or of false historical recollection.

This is the one permitted substantive revision. Its named final modules preserve the original profile modules and freeze unchanged. Both judges receive the same final prompt and schema. They may run once more on the same40development controls to document engineering performance; those repetitions are not independent examples. No further prompt revision, including in response to held-out failures, is permitted. Calibration keys remain frozen from the initial template generator. Research allocation is determined from timing only before new research labels are inspected.
