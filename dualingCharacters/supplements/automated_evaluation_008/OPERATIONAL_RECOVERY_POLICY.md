# Exact-ID time-limit recovery

This prospective operational rule was written while the Qwen research worker was healthy, before examining its held-out or research semantic labels. Its real-input timing is slower than development profiling. The active worker is not interrupted or extended in place.

If the existing hard reservation ends before all fixed tasks are persisted, the original failed attempt and costs remain. A single continuation selects **only IDs with no persisted record**, in the original fixed order. It does not select by validity, label, condition score, or calibration performance. The same base model, revision, prompt, schema, decoding, output budget, and one-format-repair policy apply. Both original and continuation inputs, outputs, raw hashes, and reservations remain in provenance. Generated but unwritten outputs are unavailable; their costs are counted and this limitation is disclosed.

The continuation input list, code, and admission are separately frozen before execution. Admission still uses the original project ceiling, obligations, contingency, stage four-hour cap, and session cutoff. `semantic_analysis_complete` composes unique persisted records, rejects duplicate actual observations, and retains all missing planned units. It never chooses the better of two labels. Original `semantic_analysis_v2` remains available unchanged. If no time-limit failure occurs, this rule is unused and no continuation is launched.

The policy changes operational completion, not the scientific sample, endpoint, prompt or stopping-by-result rule. Longer bounds for not-yet-launched probe/sample calls can be recorded from actual timing alone, without changing their frozen selected IDs.
